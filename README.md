# 对话拾遗

**让插件发言、@Bot 和引用消息回到对话里。**

AstrBot 的普通对话历史可能漏掉插件发送的结果，平台转换也可能让 @Bot 和引用消息丢失信息。「对话拾遗」保留这些上下文，让模型知道刚才发出了什么、用户在叫谁、引用的是谁的消息。

适用于 **OneBot / aiocqhttp** 和 **QQ 官方 Bot（API / Webhook）**。

## 看看实际效果

用户抽卡后接着问“这是谁”，模型可以沿着正常对话读到抽卡结果：

```text
用户：珈宝你好
助手：你好
用户：~抽卡
助手：纳兹·多拉格尼尔 [角色图片]
      💡回复任意表情和 TA 结婚

      【插件发言来源：抽卡插件；插件：draw_plugin；版本：1.0；发送时间：……】
用户：这是谁？
助手：这是《妖精的尾巴》里的纳兹。
```

抽卡结果保留原文，作为一条普通 `assistant` 消息放回它发生的位置。插件来源等描述附加在这条消息末尾，供模型理解上下文；群里实际发出的插件消息保持原样。

触发指令缺失时，会补入对应的 `user` 消息，保留 `~抽卡` 等原始前缀。用户继续聊天即可使用这些上下文，无需引用结果或发送额外命令。

## 三类上下文补全

### 插件发言

- 保存获得平台发送回执的插件消息，在下一次模型请求时按发生顺序嵌入正常对话。
- 保留结果原文，并附加插件名称、版本和发送时间；来源无法确定时标注“来源未知”。
- 支持指令返回的消息、插件直接回复，以及常见的主动推送路径。主动推送只补助手发言。
- 每个 Bot、聊天来源和会话分支独立记录，遵守当前 Bot 配置中的插件选择。
- 默认每个会话分支保留最近 **10 条**额外插件发言；1～100 是插件发言自身的上限，**0 表示不设额外上限**。是否记录由独立开关控制。
- 开启 AstrBot 的“群聊上下文感知”时，群聊补充消息与插件发言共用该功能的“最大消息数量”，合计保留最近对应条数。
- 记录会持久保存，插件重载后仍可使用；已补入的消息通过内部标记去重。

本地可读取的图片会随记录保存；远程图片保留链接，读取时需要链接仍然有效。模型识图取决于所用模型的能力。文转图等装饰处理前的指令结果会优先留存文本。

### @Bot 文本

当平台把用于唤醒机器人的 At 消息段从纯文本中移除时，插件会在模型请求前恢复其含义：

```text
用户实际发送：@珈宝 你看到我在叫你吗？
模型看到的文本：@珈宝(QQ: 123456789) 你看到我在叫你吗？
```

支持按平台检测昵称，也可以固定显示名称和文本模板。只处理指向当前机器人的 @，该功能适用于群聊。

### 引用消息

在 OneBot 中，如果引用消息缺少发送人信息，插件会查询原消息，补回昵称、ID 及可恢复的文本和图片，让模型知道被引用的内容是谁发出的。

```text
用户引用了 Alice 的图片：这张图怎么样？
模型的引用上下文：(Alice, QQ: 10001): [图片内容]
```

适配器已提供完整引用信息时直接使用已有信息；查询超时后继续处理原消息。

## 安装与启用

在 AstrBot 插件管理页，通过仓库地址安装：

```text
https://github.com/TenmaGabriel0721/astrbot_plugin_preserve_atbot
```

也可以把插件目录放到 `data/plugins/astrbot_plugin_preserve_atbot/`，然后重载插件。

安装后，在插件管理页启用 **「对话拾遗」**，并在需要使用的 Bot 配置中选择它。默认配置即可工作。

插件内部标识为 `astrbot_plugin_preserve_atbot`，配置与记录使用这一标识。已安装旧版的用户更新后可继续使用已有配置和记录。

## 配置

### 插件发言记录

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `record_plugin_messages` | `true` | 将获得发送回执的插件发言嵌入正常对话 |
| `recent_plugin_message_count` | `10` | 插件发言自身的保留上限；1～100 保留最近对应条数，0 不设额外上限；群聊共享上限仍生效 |

“10 条”指插件发言自身的保留上限。开启群聊上下文感知后，还会使用当前 Bot 的“最大消息数量”作为共同上限。例如群聊设为 **42**：

- 插件条数设为 **0**：群聊补充消息与插件发言按发生顺序合计最多 **42 条**。
- 插件条数设为 **10**：合计仍最多 **42 条**，其中插件发言最多 **10 条**。
- 一条含多行文字的群消息计作一条；每条获得发送回执的插件发言计作一条。

超出共同范围的旧群聊补充内容会退出请求，旧插件发言也会退出并清除对应补录记录。已写入历史的群聊补充块会更新为当前范围，避免跨多轮重复累积。插件发言继续逐条嵌入正常对话，保留原文和来源。

此共同上限控制“群聊上下文感知”的补充消息和插件发言。当前用户提问、正常模型对话及工具调用链仍由 AstrBot 的会话历史设置管理。私聊或未开启群聊上下文感知时，只使用插件自身条数；此时 `0` 表示不限制插件发言数量。

关闭 `record_plugin_messages` 会停止记录和补入，并恢复 AstrBot 原有的群聊上下文处理。已有正常会话不会因此被清空。实际发给模型的内容仍受 AstrBot 的历史裁剪和模型上下文长度影响。

### @Bot 文本恢复

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `bot_display_name` | `Bot` | 平台未提供昵称时使用的显示名称 |
| `prefer_detected_name` | `true` | 优先使用平台检测到的机器人昵称 |
| `marker_template` | `@{name}` | 恢复后的文本格式，必须包含 `{name}` |
| `platforms` | `qq_official`、`qq_official_webhook`、`aiocqhttp` | 指定在哪些平台恢复 @Bot 文本 |
| `sync_event_message` | `true` | 将恢复后的 @Bot 文本同步到消息事件，供后续插件读取 |

例如，希望固定使用“珈宝”这个名字：

```json
{
  "bot_display_name": "珈宝",
  "prefer_detected_name": false,
  "marker_template": "@{name}"
}
```

检测到机器人 ID 时，`{name}` 也会包含该 ID。`platforms` 控制 @Bot 文本恢复，列表留空时不限制平台；插件发言记录和引用补全各自按支持的平台工作。

### 引用补全与调试

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `enhance_quote_sender` | `true` | 在 OneBot 中补全引用消息的发送人及可恢复内容 |
| `quote_sender_fallback_name` | `Unknown User` | 查询后仍缺少昵称和有效 ID 时使用的名称；留空则不添加回退名称 |
| `quote_sender_timeout` | `5.0` | 单次引用消息查询超时，单位为秒，范围 0.1～30 |
| `debug_log` | `false` | 输出 @Bot 检测来源及引用发送人的补全信息 |

## 平台支持

| 功能 | OneBot / aiocqhttp | QQ 官方 API | QQ 官方 Webhook |
| --- | --- | --- | --- |
| 插件发言记录（群聊、私聊） | 支持 | 支持 | 支持 |
| @Bot 文本恢复（群聊） | 支持 | 支持 | 支持 |
| 引用发送人查询与补全 | 支持 | — | — |

记录覆盖指令返回、`event.send()`、`context.send_message()`、OneBot 直接 API 发送，以及官方 Bot 群聊/C2C API 发送的常见路径。其他发送方式需要确认是否经过这些入口。

## 使用边界与排查

- **以平台回执为记录依据。** 无回执或发送失败的消息会跳过记录；仅部分内容获得回执时，模型上下文中会附上部分发送的说明。
- **从启用后开始记录。** 安装前未被保存的插件发言需要新的消息触发记录。
- **在下一次模型请求中生效。** 发送时独立保存记录，模型请求时合并，再由 AstrBot 的正常历史保存流程持久保存完整会话。
- **媒体能力取决于原内容和模型。** 原图不可用时标注不可用；音视频和其他附件保留可识别的类型提示。
- **唤醒由 AstrBot 决定。** @Bot 恢复补回文本含义，机器人是否回复仍由 AstrBot 的唤醒设置控制。

若插件发言没有进入上下文，先检查「对话拾遗」是否全局启用、当前 Bot 配置是否选中，以及记录开关是否开启，再确认插件消息获得了发送回执、后续聊天触发了模型请求。条数设为 0 仍会记录。

若 @Bot 或引用信息缺失，可以开启 `debug_log`，检查平台设置、@ 的目标和 OneBot 的 `get_msg` 查询结果。

记录保存在：

```text
data/plugin_data/astrbot_plugin_preserve_atbot/sent_history.db
```
